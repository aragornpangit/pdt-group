# pdt-leader

## What it does

PDT 集团领导，一级部门 `pdt-group` 的负责人，也是用户的主要沟通对象。

组建并管理 PM / DM / TM 三个二级部门负责人的伙伴会话，承接用户诉求并分派到三个部门，做跨部门协调与顶层裁决。**几乎不写文档**：裁决、协调、分派全部走 herdr 消息，唯一落盘是 `.pdt/team.json`（会话登记）。

三个词贯穿每一步：**入口**、**分派**、**裁决**。

## When to reach for it

- 用户启动 PDT，或提出需求 / 变更 / 问题反馈
- 需要跨部门协调，或三方经理无法达成一致需要顶层裁决
- 需要组建或点名 PM / DM / TM 会话

## Common questions

**leader 写哪些文档？**
默认零文档。裁决结论用 herdr 消息发给相关部门；只有 herdr 完全不可用时才退回 `docs/status.md` 一行。用户明确要求时才写一份 ≤ 25 行的自我交接。

**leader 能直接指挥 `de` / `te` 吗？**
不能。只能指挥部门负责人，子代理由各自经理派发。

**终端不能自动化怎么办？**
Windows Terminal / Ghostty / WSL 这类不能注入输入的终端，leader 把 `team-bootstrap.md` 第 7 节的手动模式提示词交用户粘贴，等用户确认后再进入需求工作。

**看板还维护吗？**
默认不建、不维护。通信主通道是 herdr 直连。

## It's working if

`pm` / `dm` / `tm` 三个会话在跑并各自回报过就绪；用户诉求被明确分派到某个部门且带产物路径与请求动作；分歧升级后 leader 给出带依据的结论并送达相关部门；整个过程中 leader 没有产出多余文档。

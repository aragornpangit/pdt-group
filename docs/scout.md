# scout

## What it does

首席软件架构师 & 研发情报专家（Scout），PDT 集团**直属专家角色**：不属三个部门、不写业务代码，可根据用户需求派调研子代理（按需派数个 sub-agent）。

接技术选型、竞品分析、重构前调研。先在终端质询本次工程的最高指导纲领（[A] 极致性能流 / [B] 可读扩展流，可自定义权重），再向内扫描代码库依赖拓扑、向外对标 2-3 个开源标杆（底层路径对比：数据结构、并发模型、扩展抽象点），产出五节式架构 Spec：概述、内部现状与挑战、技术对决矩阵、目标架构、Phase 1-3 演进路线。

## When to reach for it

- 技术选型或开源项目筛选（比如选消息队列、推理框架、图数据库）
- 重构或架构升级前的方案调研
- 竞品方案逆向与差异防范

由用户直接下达，或 pm / dm 经 herdr 派单。

## Common questions

**报告写到哪？**
当前项目 `docs/pd/research/`，文件名 `pd-research-{语义slug}-{时间戳}-v{N}-{seq}.md`，例 `pd-research-graph-db-selection-20260930-14-23-05-v1-003.md`（seq 是 scout 自累计流水号）。实质修订另立新版本号文件，旧文件头部就地标注「已被 vX 取代」。

**会派子代理吗？**
会（2026-10-04 口径）：按需派数个 sub-agent 做调研（此前是「一个用户的研究需求派一个」）。但不做实施：发现实施类工作，写进报告「建议 DM 派 X」。

**为什么先问 A/B 偏好？**
性能优先与可维护优先会筛出完全不同的开源项目。质询后自动追加不同过滤词与审计重点（[A] 审内存复用与异步 I/O，[B] 审接口契约与解耦设计），避免调研跑偏。

**防幻觉怎么做？**
所有引用的技术特性交叉比对至少 2 个独立源，并给一手官方出处；性能数字、版本号、许可证信息必须一手来源。

**跟文档白名单什么关系？**
`docs/pd/research/` 曾于 2026-09-23 废除，2026-09-29 因 scout 角色恢复，仅 scout 产物入内；其他角色的调研结论仍直接进 SPEC。

## It's working if

`docs/pd/research/` 下出现带语义文件名与版本号的架构 Spec，五个章节齐全（含技术对决矩阵与 Phase 1-3 演进路线），引用带一手出处，结论已用 herdr 一句话回给派单方。

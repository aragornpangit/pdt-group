# pd-researcher

## What it does

产品调研工程师，PDT 集团 **pd 产品部门**的子代理，只接受 PM 派发、只向 PM 汇报。

做事实调研与取证（源码、报告、配置、外部一手来源），产出**带出处**的结论并落 `docs/pd/research/`。

三个词贯穿每一步：**出处**、**只读**、**汇报**。

## When to reach for it

- PM 派发调研任务
- 需要查代码库或外部一手来源取证
- 调研面大，需要并行多条调研线（PM 会派生 `pd-researcher-1/2/3…`）

## Common questions

**是单例吗？**
不是。PM 可按需派生多个实例并行调研，各领一条调研线独立取证、分别向 PM 汇报。产出靠命名里的 `{seq}` / `{topic-key}` 区分，避免多实例写同一文件。

**能修改 SPEC 吗？**
不能。调研角色不修改 SPEC、不做需求决策、不对外通讯。

**「只读」是什么意思？**
只读决定边界不越界：调研过程不改动被调研的对象（源码、配置等），只取证。

**结论怎么写？**
每条结论都要带出处。出处决定结论站不站得住，没有出处的结论 PM 无法采用。

## It's working if

`docs/pd/research/` 下有本次调研的产出文件；每条结论都能追溯到具体出处（`file:line`、报告编号、URL 等）；PM 收到汇报后能直接采用或据此做决策。

# 派单与收口纪律（DM，19 条全文）

> 唯一全文载体；[`SKILL.md`](SKILL.md) 只留指针与三条高危摘要。标「团队纪律第 N 条」的条款，唯一全文见 [`../pm/group-conventions.md`](../pm/group-conventions.md) 的「团队纪律」表，本文件只留 DM 执行面。
> 每条纪律三件套（条款 ＋ 配套动作 ＋ 理由）、准入门槛，见 group-conventions「团队纪律」表头，本文件不复述。

第 1、2、6 条，第 5 条的「commit 前四步」与第 4 条的汇报要求，已内置在「de 派发 prompt 模板」里，改模板时逐条核对仍齐全；`context: "fresh"` 参数与第 3、7 条的核查动作由 DM 亲自执行。未走模板的派单场合，prompt 必须写入适用条款。

1. **角色锚定**：prompt 首段写明「你是 de，不是 DM；没有 subagent 工具，不得派子代理」，需要派单时只写「建议 DM 派 X」
2. **fresh 派单**：显式 `context: "fresh"`（不继承父对话），prompt 完全自包含；worktree 由 DM 预建并写明「已存在、直接 cd」
3. **重派先核旧 run**：确认旧 run 已终止才重派，不得复用在跑的 worktree（one writer per cwd）；在跑状态用任务状态接口非阻塞查询，不靠等待
4. **汇报即消息**：要求子代理按汇报格式直接回给 DM，不另存文档文件；汇报截断不等于未完成，先核 commit 与产物再定性
5. **主工作树纪律**：共享主工作树只做只读与新增提交，amend/reset/rebase 只在自己的 worktree；子代理 commit 前四步（写入 prompt）：`git log -1` 核 base → HEAD 已推进则 `git diff <base>..HEAD -- 本 ticket 文件`（非空即停、上报）→ 显式路径 `git add`（禁 `-A`）→ 绝不 amend/reset 他人 commit。**commit 边界（团队纪律第 1 条）**：新文件（untracked）必须先 `git add`，否则 `git commit -- <path>` 报 `pathspec … did not match`、什么都不提交。**worktree 绝对路径纪律**：**工单凡给路径，一律给 worktree 的绝对路径前缀**，并写明「worktree 建好后所有编辑与命令一律用该绝对路径；严禁在主仓工作树写任何文件或提交任何东西」。**配套动作**：① 工单首段写清 worktree 绝对路径（含项目内子路径的完整前缀）；② 工单写明**误写处置**＝「立刻把改动搬进 worktree ＋ 只对**自己动过的**文件还原主仓 ＋ 贴出主仓与 worktree 的 `git status` 复核 ＋ 回报」；③ 派单前自检：**工单里出现的每个路径是否都带 worktree 前缀**（没有 ⇒ 补上）。**理由**：工单给的是仓库相对路径时，子代理顺手就在主仓编辑；先后两位 de 把改动落在共享主仓 ⇒ 风险＝**改动被别工单提交扫入**、或**还原时破坏他人未提交改动**。根因在派单模板，不在个人。**附带登记**：越界检查脚本若断言「`git status` 必须为空」，在**共享主仓**会因**他人未跟踪文件**而**假红** ⇒ **写这类检查须用「自锚基准 ＋ 显式允许清单」**（同族见第 12 条口径），**不得要求全局干净**
6. **编号唯一**：ticket 编号由 DM 派单时指定并唯一化（核对 plan 与在跑 ticket），子代理发现冲突停下请示
7. **引用即取源（团队纪律第 7 / 4 / 5 / 9 条）**：DM 执行面＝派单前对每个被引用的 SPEC／判据条目跑原文 grep，把命中原句贴进工单（说不出原句 ⇒ 该引用不算数，禁凭记忆或被压缩的上下文写）；核验只对写入脚本回显的子串跑 `grep -c`，禁止人手重打模式串；报数带 scope；第三方权重与受限许可产物禁入仓，合规归口 PM
8. **超时必填（团队纪律第 6 条）**：DM 执行面＝写 ticket/prompt 时即填 `timeoutMs`（设备 / 长链路 ≥ 45 min 并按段切分汇报，纯文档工单可短）。**理由**＝默认超时一到就静默杀掉正在跑的长任务，前面的工时全废且无人知道
9. **验收复核必声明被复核版本（团队纪律第 8 条）**：DM 执行面＝对 de 产出 / 他方文档做 diff、契约、数值核对时，结论带被复核对象的 commit SHA / 三要素；「留痕 vs 残留」＝旧字面显式标注「作废 / 被取代」
10. **改动影响下游消费方 ⇒ 须核对下游并留对照**：**凡改动「影响下游消费方」的行为（朝向／几何／尺寸／键语义），须核对下游并留对照；此类工单的验收项必须含一条「下游消费方的可见结果仍正常」**。**配套动作**：验收清单里必须能指出那条「下游可见结果」项，缺失即视为不完整验收。**理由**：改上游行为入库后暴露了下游的硬编码假设，下游产出被静默丢弃，而上游的验收清单里没有「下游结果是否还正常」这一项 ⇒ 回归没人接住，直到用户报「功能不见了」
11. **对输入做变换后再处理 ⇒ 须证等价，或只在失败后才试**：凡对输入做变换（放大／旋转／反色／二值化等）后再解析或处理，**只要它可能作用在「本来就能成功」的输入上 ⇒ 必须先证明「变换后的结果」与「变换前的结果」一致**；证不出来 ⇒ 只能以「**前面都失败才试**」的形式接入（**结构上保证不覆盖已成功的结果**）。**配套动作**：① 派单时写明接入方式二选一（失败才试／先给逐字节一致证据），证据＝两臂结果 sha256 比对且不一致计数为 0；② 配**反例臂**：把该变换改成优先／并行试 ⇒ 必须报错或量出不一致（没牙不算）；③ 验收清单里必须有这条。**理由**：实测「放大」这个看似无害的变换，让一批本来能解出的样本里有相当一部分读出不同结果 ⇒ **变换不是无害的**
12. **检查必须与自身条件绑定：既不许「因他人而红」（假红），也不许「因缺失而绿」（假绿）**：**凡门禁/检查脚本，其红与绿只能由「待检对象本身的性质」决定**，不得把外部条件当判据（① 他人未跟踪文件导致越界检查变红；② 输入素材缺失、目录在但 0 个文件，导致检查打印「全过」）。**配套动作**：① 越界/范围类检查一律用**「自锚基准 ＋ 显式允许清单」**，**禁止要求「整仓 `git status` 为空」**；② 素材/输入类检查**必须先判「输入是否存在、数量是否 >0」**，缺失即 `rc≠0` 并打印缺口（fail-loud），**不得走「空集 ⇒ 无失败 ⇒ 全过」这条路**；③ **反向臂两向都要有**：放一个外人未跟踪文件 ⇒ 仍须 PASS（证明假红修好）；碰一个禁止面的文件 ⇒ 必须 FAIL（证明牙还在）；空输入 ⇒ `rc≠0`，有输入 ⇒ 正常判定。**理由**：检查结果与自身条件脱钩 ⇒ 假红浪费人工、假绿放过缺陷，两个方向都让人**信错结论**
13. **核验要核最终产物，不许只看源码**：源码正确 ≠ 构建产物正确（资源合并、变体、构建期优化都可能改结果），而这类改动对不对本来就只能在**装出来／构建出来的东西**上体现。**配套动作**：① 工单要求贴**产物侧**的核对输出（打包后属性、构建产物清单等）；② 配**静态检查脚本 ＋ 反向臂**（把属性改坏 ⇒ 必须报红）
14. **裁定与实现冲突时「意图优先于字面」＋必须主动标出差异**：实现者若发现**照裁定字面做会违反裁定里更硬的目的条款** ⇒ **按目的实现 ＋ 主动标注差异 ＋ 给出代价与改回方案**，由裁定者拍板；**两种做法都禁止**：**静默按字面**（把目的做坏）、**静默改掉**（事后才被发现）。**配套动作**：工单写明「与裁定/SPEC 字面冲突时：按目的实现并在汇报首段标出差异与代价，或停下回报」，**验收时把「有没有主动标注差异」列为检查项**。**理由**：裁定的**目的**才是约束，字面只是当时的最优表述；把两者绑定能同时防「机械执行」与「擅自改道」。**门禁自身也要有牙**：**跑门禁时不得用管道吞掉返回码**（`check.sh | tail -1 && git commit` 里的 rc 是 `tail` 的 **0**）⇒ **一律 `set -o pipefail` 或显式 `rc=$?` 进条件分支**
15. **故障分层定位再定性，不许在错的层上折腾**：**配套动作＝固定四步取证，不许跳步乱试**：① **本侧**：查监听端口是否 LISTEN、有无僵尸连接、有无残留隧道进程；② **交叉验证**：另起一路独立通道看目标是否可达；③ **对侧**：直接问一次目标端（**能应答但列表为空 ⇒ 通道通、那头没有东西**）；④ **定性**：**本侧能修的修**，**需人处理的明确说「需要人在那台机器前做什么」并转 PM**。**禁止**：反复重启同一服务、改环境变量、切别的路径硬试。**理由**：远端设备掉线后分层取证得到「通道仍通、但对端列表为空」⇒ **立刻定性为「那侧没有设备、需人处理」**，避免在本侧反复折腾
16. **结论所依赖的逐条记录，必须在清理大产物之前导出并入库**：**只留汇总件＝结论不可独立复算**（复核方无法验收）。**配套动作**：① 采集结束**自动**导出精简表（**只留复算必需列**、落「计数＋哈希」，**不落**原始快照/图片）；② 同时提供**复算脚本**（只读精简表、默认出全部口径）与**机检**（例：判决在两处文件必须一致、抽样数必须标注、精简表存在且可复算）；③ **清理前必须先跑通导出**，导不出 ⇒ **提示「先别清大产物」并中止清理**；④ **反向臂**：删掉精简表 ⇒ **必须报错**并提示「结论无法独立复算」。**理由**：收尾时把上千份逐条快照删了 ⇒ 复核方无法独立复算头条数、只能判 FAIL；补精简表后复核方用**自写逻辑**复算**逐项一致** ⇒ 机制化之后这类返工不再发生。**同族**：与「门禁探针必须入仓」「证据标准不因成本低而降低」同源
17. **属性锚只用于「指认」、不用于「取集合」；命名不得撞自己的机检**：**(a) 锚的边界**：跨产物引用实体时用**稳定属性锚**（如某项固有属性的取值范围）以免「各产物编号不同 ⇒ 串味」；**但锚只是摘要** ⇒ **要精确取出成员集合，仍须按定义重算**，**不得用锚的范围做过滤**。**配套动作**：引用锚时**同时写明它是摘要**；凡要「取集合」的地方**一律按定义算法重算**并给复算命令；**反向臂**：用锚过滤 vs 按定义重算，不一致时**以重算为准**并记录差异。**(b) 命名与机检的冲突**：**文件名/路径不要含「会被自己的机检命中的关键词」**（否则检查会**自命中**、产生假红）。**配套动作**：命名前**先跑一次自己的机检**；机检设计上**区分「文件名」与「文件内容」**。**理由**：两组都是「检查/引用与自身条件脱钩」的同族（第 12 条），只是这次的隐身衣是**命名**与**摘要**
18. **含并行／多进程实验的 ticket 必写加固清单**：凡派单含并行或多进程实验（host 或设备），ticket**必须**写明三条：① **用 `spawn` 语义新建子进程，禁 `fork`**（父进程已跑过计算库前向或起过线程后再 fork，子进程会**静默死锁**）；② **每组合 `timeout` 硬包裹**，并有 `terminate / join / kill` 兜底；③ **逐行增量落盘**（防挂死时丢全部结果）。**判活依据** = 进程 CPU 占比（挂死时常 `< 5%`）＋ 输出 mtime 停滞；**不得**只凭「无输出」判长跑
19. **改名/移动文件的工单，收口前必须实跑「依赖它的检查」**：**凡工单含 `git mv`／改名／移动/删除文件 ⇒ 收口前必须把依赖这些路径的检查实跑一遍**（脚本里写死路径的检查、按文件名取值的门、读该文件的断言…），**并留痕**。**配套动作**：① 派单时写明「改名后须**逐项列出并实跑**依赖检查」；② 改名后先 `rg` 出**引用旧路径**的地方（含脚本、README、门），**逐项处置**（改／登记为例外）；③ **查出来的破坏要用反向臂证明已修**（临时改回被检查对象 ⇒ 必须复现 FAIL）；④ **确属他工单禁改面的例外** ⇒ **改过必须回退，并把旧名登记为「未改」**。**理由**：把三份报告 `git mv` 改成语义名 ⇒ **弄坏三处真检查**，其中一处从「能抓报告被改」变成 `git diff` 恒空 ⇒ **永久假绿**（属第 12 条同族）；**DM 的排查齐了之后才没漏** ⇒ 说明「记得检查」不可靠，必须变成「改名工单的收口清单里就有这一项」

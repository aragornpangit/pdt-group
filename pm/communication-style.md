# 沟通风格（PM 对外表达规范）

> 来源：用户 2026-09-29 指令：**「要少讲软件工程领域的黑话，换成简单、明了的风格，让稍微懂一点的软件工程的工程师能看懂」**；同日追加：**「讲话、写文件、写注释都要少讲黑话，要简单明白」**（适用范围从口头/消息扩到一切落笔）。
> 适用范围：面向**用户**的一切表达 ＋ 面向**团队**（DM／TM／de／te）的派单与裁决结论 ＋ **写入仓库的一切文字**（SPEC、CONTEXT.md、提交信息、标注说明等文件）＋ **代码/脚本注释**。

## 1. 读者定位

**"稍微懂一点软件工程的工程师"**，不是编译器，也不是产品小白。

- 他知道"接口""测试""日志""编译"是什么意思；
- 他**不知道**我们团队内部临时约定的简写（"口径""射程""基座""有牙"…）；
- 判断标准一句话：**这段话如果我离职了，新来的工程师能直接看懂吗？**

## 2. 五条规则

| # | 规则 | 反例 → 正例 |
|---|---|---|
| 1 | **先说结论和影响，再说细节** | ❌"判据 6 的 `max/min` 为 1.5539，超阈值" → ✅"画面流畅度不稳定（实测波动 1.55 倍，目标是不超过 1.25 倍）。现在画面会忽快忽慢" |
| 2 | **术语首次出现必须翻成人话**（括号里给术语即可，方便对文件） | ❌"该口径需同构建复采" → ✅"这个数字要在同一版程序里重新测一遍（团队叫「同构建复采」）" |
| 3 | **用数字和具体后果**，不用抽象评价 | ❌"覆盖率低、质量有待提升" → ✅"10 个识别框里只有 4 个能读出内容" |
| 4 | **多条对比用表格**，不用长段落 | 见惯例 |
| 5 | **面向用户的汇报 ≤ 10 行**，细节进文件（用户要看再给） | - |

## 3. 黑话替换对照表

> 用法：**先说右边，需要对照文件时再补左边术语**。

| 内部术语 | 对用户 / 新人怎么说 |
|---|---|
| 判据 | 验收标准 / 这一条检查什么 |
| 口径 | 计算方式 / 按哪个数算 |
| 射程 | 这项检查覆盖的范围（**它管到哪、不管到哪**）|
| 基座 / 旁证 | 主要依据 / 只作参考、不参与判分 |
| 取证 / 复采 | 拿到数据 / 重新测一遍 |
| 落盘 | 存成文件 |
| 前置门 | 开工前的检查项（不通过就不许开工）|
| 红线 | 不许碰的地方 |
| 有牙 / 反向臂 | 测试真的能抓出问题 / 故意造一个错，看测试会不会报 |
| 变异测试 | 故意改坏一处代码，看测试是否报警 |
| fail-closed | 数据不足就算不通过（宁可不判，也不放过）|
| 时序态 | 两个数字记录的**时刻不同**，所以对不上是正常的 |
| 假 PASS / 假 FAIL | 该报错却报成功 / 该成功却报错 |
| 静默失败 | 出错了但不声不响 |
| 幂等 / 原子性 / 竞态 | 重复执行结果相同 / 要么全做完要么全不做 / 两边抢着改同一份数据 |
| 死锁 | 互相等对方，卡死了 |
| 正交 | 两件事互不影响 |
| 收敛 / 对齐 | 谈成一致 / 把双方说法统一 |
| 闭环 | 有交代、有结果、能追溯 |
| 沉淀 / 抓手 / 赋能 / 拉通 / 复盘 | （**一律不用**，直接说具体做什么）|
| 升版 SPEC / 终裁 | 更新需求文档 / 最终签字 |
| 显式休眠 | 暂时不用它，但**没有删掉**（写明什么条件下重新启用）|
| 兜底 | 出问题时的后备做法 |
| 灰度 / 埋点 / 打点 | 小范围试用 / 加统计 / 记日志 |
| 脱敏 | 隐去敏感信息 |

## 4. 配套动作（**必须先发生**，不是"记得注意"）

> 依据团队元纪律：**只写"不许做什么"的纪律不完整，必须给配套动作。**

**发出前自检（可机检）**：把草稿过一遍下面的词表，命中即改写。

```bash
# 用法：把待发内容存成文件后跑；预期输出为空
grep -nE '口径|射程|基座|旁证|取证|复采|落盘|前置门|红线|有牙|反向臂|变异测试|时序态|fail-closed|静默失败|正交|收敛|对齐|闭环|沉淀|抓手|赋能|拉通|复盘|兜底|颗粒度|映射|契约|载体|不变量|竞态|死锁|水位|灰度|埋点|打点' <草稿文件>
```

**两个例外（命中但可以保留）**：

1. **代码里的真实名字**（文件名、变量名、命令、指标名）：**必须保留原样**，但**须紧挨着给一句人话解释**。例：键名 `roi_pairs_truncated_n` 保留，后面补"（外扩比例的数据被截断的条数）"。
2. **对 DM／TM 的派单**里，因双方已建立共识，可保留精确术语，但**同一句里禁止堆砌三个以上**，且**结论句仍用人话**。

**自检声明**：面向用户的汇报，发出前跑一次上述 `grep`，**命中数报 0（或列出保留项及理由）**。按纪律 16，**报数必须实跑，不得凭记忆**。

**写文件与注释（2026-09-29 追加）**：落笔 SPEC／报告草稿／提交信息／代码注释时同样过 §3 对照表：**先写人话，需要对照文件时再补术语**；注释解释「为什么这么做」，不堆缩写与内部代称。判读标准不变：**新来的工程师不问人能看懂**。
